# PBX-саботаж

**Турнир:** SolarCTF · **Категория:** forensics

**Статус:** Решено.

## Кратко

Конфиг АТС разделён между TFTP, HTTP и SMTP. Пароль передан тремя звонками через RTP telephone-event и звуковой DTMF.

## Решение

### 1. Собрать контейнер из разных протоколов

TFTP-файл `pbx_backup.part1`, HTTP multipart `pbx_backup.part2` и SMTP MIME `node_report.dat` содержат части по 623, 623 и 622 байта. У каждой 18-байтный заголовок `SOLPBKCH`, index, count, uint32LE длина и CRC32. Проверить заголовки и CRC, затем склеить полезные данные по индексам 0,1,2. Получается 1868 байт.

### 2. Восстановить единый пароль

Для звонков с RTP source ports 21294, 21438 и 20176 декодировать telephone-event PT101 и PCMA PT8. Дубликаты событий объединять по RTP timestamp, тоны сопоставлять DTMF-матрице, оба канала упорядочить во времени. Второй и третий звонки начинаются с двух последних символов предыдущего — `BA` и `89`. Удалить повторы и склеить три новые части по 32 ASCII-символа, получив пароль длиной 96 байт. Отдельные звонки не являются отдельными паролями.

### 3. Расшифровать активную конфигурацию

Контейнер `SOLPBK01`, version 2: iterations uint32LE по offset 9 = 60000, salt `[13:29]`, IV `[29:45]`, длина uint64LE `[45:53]`, CRC32 `[53:57]`, ciphertext `[57:]`. PBKDF2-HMAC-SHA256 с dklen=32 и AES-256-CTR дают INI длиной 1811 байт с CRC32 `9e34e966`. Нужен `secret_code` из `[backup-v2]`; `[backup-v1]` устарел. Независимый разбор PCAP, DTMF и CTR подтвердил результат.
